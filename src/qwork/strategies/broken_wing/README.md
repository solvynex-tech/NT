# BrokenWingStrategy

## 输入与运行

输入标的、可占用保证金预算、并发组合数量与可选 Gamma 排序。只从 IV 偏斜较大侧的破翼蝴蝶候选选择；计划平仓时模型获利概率必须 **>70%**，最大到期盈利 / 最大到期亏损必须 **>1**。Gamma 不是资格过滤，每个报价事件按绝对净 Gamma 重新排序。

```powershell
.venv/Scripts/python.exe -m qwork backtest --symbol SPY --margin 10000 --date 2026-10-02 --interval 1m --max-positions 3 --universe-size 6
# 关闭 Gamma 排序
.venv/Scripts/python.exe -m qwork backtest --symbol SPY --margin 10000 --no-gamma
# 明确指定账户环境后启用原生 IBKR 执行
.venv/Scripts/python.exe -m qwork trade --mode paper --symbol SPY --margin 10000 --account-id DU1234567
```

`trade --mode live` 使用明确的实盘账户。此代码路径尚未进行真实市场委托验证；本次没有启动自动实盘委托。连接参数读取 `.env` 的 `IBKR_HOST`、`IBKR_PORT`、`IBKR_CLIENT_ID`；账户必须与连接实际返回的账户一致。

## Actor 与原生职责

策略可复用曲面、期限结构、筛选和组合盈亏 Actor。IBKR live 节点注册全部四个 Actor，策略读取筛选主题与原生期权 QuoteTick。委托、成交、订单状态、持仓和资金由 Nautilus 管理；组合路径状态归策略管理。

`analytics.py` 使用 QuantLib 估值和 Gamma，SciPy Brent 求当前盈亏平衡点。每次期权腿 / 组合报价更新重算；使用中间腿 Call / Put 平价推断远期价，不单独查询股票。四条腿参考报价时间差最多 1 秒，组合 BBO 也须与它们对齐，禁止拼接新旧分钟。报价年龄和腿间时间差是两个独立检查。

## 建仓与去重

每组预留至少最大亏损乘 1.1；live 另通过 IBKR `whatIf=True` 查询初始保证金，以两者较大值预算。实际委托始终经 NT，what-if 只作预检查。按预算 / 最大并发组数分配额度，再按可用预算、数量上限和报价数量向下取整。未成交开仓单也占额度。

组合身份为标的、到期日、方向、三行权价；同一交易日每种已成交组合只建仓一次，完成身份跨重启保留。限价开仓，市价平仓；部分成交先撤开仓剩余量，确认终态后平仓。平仓拒绝 / 未完成会暂停新开仓。回放和 live 共用 `lifecycle.py`：默认中点限价、120 秒超时、撤单确认后冷却 60 秒、最多 3 次入场；撤单无确认不释放预留，迟到成交数量不一致则冻结并要求对账。有限合成盘口只属于回放。

## 持久化与账户风控

`recovery.py` 在独立账户锁下保存 SQLite 策略意图，目录为 `data/private/trading/<mode>/<account>/`。启动通过 NT reconciliation 获取原生订单和券商逐腿持仓，按真实成交数量核验共享腿。无法解释的订单、其他账户仓位、缺失的成交历史及跨日残余暴露阻止恢复；不凭旧日志重发委托。适用于专用账户，实际 IBKR 故障演练尚未完成。

`risk.py` 使用已报告 USD 净值和可用资金，不用现金替代净值；数据缺失或过期禁止新开。默认当日亏损阈值 500 USD、峰值回撤 1,000 USD、资金缓冲 100 USD、账户数据最长 300 秒、连续拒单限制 3 次。日内基准为首次有效净值；触发原因随状态持久化。CLI 支持 `--daily-loss-limit`、`--drawdown-limit`、`--account-max-age`、`--funds-buffer`。STOP 文件停止开仓并管理已核验组合退出；进程退出不代表平仓。

## 退出规则的明确解释

1. 浮盈达到该组合实际建仓成本计算的最大到期盈利的 70%：市价平仓，确认成交后永久完成本次运行的该身份组合。
2. “最大盈利区域”定义为中间行权价 ± 半个较窄翼宽。未进入该区，价格先穿越 tick 重算的当前盈亏平衡点时，记录提前平衡标记。
3. 标记后价格向远离中间行权价方向移动，且可平仓利润从阈值上方跌穿初始到期盈利平台金额的 20%：市价平仓，再从剩余不同组合选择。初始负浮盈不会误判为利润回撤。盈利平台指 Call 左侧 / Put 右侧的恒定到期收益。
4. 日内强制：纽约 15:30 后不新开，15:55 撤未成交开仓并平仓；提前收市日分别在收盘前 30 / 5 分钟执行。断线、拒单、无成交不能宣称已平仓。

## 回测与限制

候选仅用入场时已知曲面，固定研究合约池，之后用到达报价重新检查开仓硬条件；不从未来结果选组合。默认使用当天计划强平时间作为概率期限，QuantLib 将期权剩余时间滚到该时点，计预计价差、滑点和佣金；IV 固定，不模拟其变化。`--probability-horizon expiration` 切回到期概率口径。两种口径都不是历史或完整路径胜率。

真实 Theta NBBO 缓存到 `data/history/`。当前套餐的 tick 历史请求被拒绝，1m 回测只验证分钟观察点。

NT 不为 spread 本身创建持仓。因此回测将合成组合 BBO 放入乘数 100 的原生线性记账代理，保留原生现金、费用、订单和持仓报表；这不是交易真实期货，也不是 BAG 成交保证。费用为每张每边 0.65 USD；回放默认额外固定腿滑点 0，可用 `--leg-slippage 0.01` 做压力情景。live 模型仍保留每腿 0.01 的成本假设。研究保证金不是券商真实保证金。

回放的平仓等待当前合成 BBO，避免定时器在新分钟数据到达前使用上一分钟报价；退出原因持续保留。每次回放自动生成 `audit.json`，对账原始 NBBO、共享腿数量、费用、现金、预算与日内平仓；失败时报告与命令退出码明确标错。

结果在 `data/backtests/<run>/README.md`、`report.json`、原生 `orders/fills/positions/account.json` 和 `events.jsonl`。风险中性概率与实际样本胜率分别报告。重启读取持久意图后必须与原生订单和逐腿仓位核验；成交证据不足时不继续交易。文件和离线测试不代表经过验证的无人值守实盘能力。
