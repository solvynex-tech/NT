# 交易台稳定性与布局验收

## 当前定位

当前是可运行的本地期权研究与原生回放工具，并有隔离的交易入口。专业实盘稳定性仍未验收。测试数量、短时 HTTP 响应和单日回放不能换算成生产可靠性百分比，也不能证明长时间运行或券商恢复正常。

## 本次改进

- K 线使用一个工作线程加一个最新待处理任务；快速选择不会不断创建线程，旧请求不能覆盖新合约。运行中的远程调用仍受数据商响应时间影响。
- 分析 / 账户节点创建和关闭串行化，关闭后禁止新的节点与策略启动。NT 构造、运行、缓存读取与销毁仍归所属线程。
- 状态数据库读锁等待从默认五秒缩短为界面专用约 50 ms；读取失败显示未知，不当作空仓。过期快照回调跳过更新，不清空账户。
- 新策略保存原子的进程注册文件，核验 PID、创建时间、完整参数及 Windows Python 子进程后才恢复只读监看。记录损坏或身份未知阻止新启动；不猜测 PID、不强杀进程、不自动重连券商。
- 浏览器独立心跳在 4 秒提示服务变慢、12 秒提示冻结；限制新启动，恢复后清除提示。此状态仅代表界面连接，不能代替账户、行情或订单回报状态。
- 使用 MT5 的市场报价 / 导航器 / 图表 / 底部工具箱布局及 ATAS 深色风格，共十四个可停靠面板；文件菜单保存 / 恢复 / 重置预设，各工作区独立保存。损坏布局回退到预设。旧折叠边栏先完成控件挂载，避免跨面板回调缺参数。菜单及视图快捷键只定位面板。
- 通过浏览器独立的输出指纹避免重复发送未变化的表格和说明；隐藏 K 线 / 净值 / 曲面延后绘制，显示时补齐当前快照。权限按钮持续核验，不被去重。分隔线拖动结束后调整图表，图表响应容器大小，并在布局稳定后校正 Plotly 尺寸；图形绘制限制在面板范围。

进程注册与业务恢复是不同层次：监看恢复不代表券商订单核验通过。启动与登记之间仍有短暂窗口；登记失败会显示错误，未登记进程不会被自动接管。运行时身份权限不足显示未知。STOP 请求也必须以券商成交和剩余持仓判断是否完成。

## 距离专业实盘稳定性的缺口

| 范围 | 尚需验收 |
| --- | --- |
| 长时运行 | 至少完整交易时段及多日运行；资源趋势、队列积压、数据年龄和报警 |
| 券商故障 | IBKR / TWS 断线、会话重建、服务与策略分别重启、迟到 / 重复回报及持仓一致性 |
| 真实组合执行 | BAG 拒单、部分成交、撤单超时、退出失败、真实数量保证金与残余腿 |
| 性能容量 | 多到期日、大期权链、多组合、实际 QuoteTick 峰值；行情到策略和发单到确认的分位延迟 |
| 用户操作 | 多窗口冲突、运行策略与当前工作区不同、未知状态的明确处置、可检索告警 |

布局仍可改进实时 K 线、账户 Greeks、可配置报价列与跨窗口联动。这些需要相应数据和操作逻辑，不能用空图或模拟账户填充。现有 K 线仍为历史期权 NBBO 中点聚合；交易工作区不展示历史数据冒充实时。

本机约 8 GB 且没有额外分页空间；完整测试、回放和桌面窗口串行验证，未修改系统设置。当前结果不证明更多窗口或更大 tick 数据规模稳定。券商执行边界见 [实盘验收](live-readiness.md)。
